# Development Workflow

This page describes the local development loop, how Hot Module Replacement (HMR) operates in DriftJS, and what happens behind the scenes when you edit a `.drift` file.

---

## 🔄 The Edit-Run Cycle

When developing a DriftJS application, your workflow consists of the following steps:

1. **Write Code**: Modify markup, styles, and scope variables inside a `.drift` single-file component.
2. **Instant Recompile**: The `driftjs-vite-plugin` catches the change, parses the file, generates updated bytecode, and wraps it as an ESM module.
3. **VM Hot Reload**: Vite pushes the updated module to the browser. The running `driftjs-dom` runtime receives the module and updates the mounted application.

---

## ⚙️ Vite HMR Under the Hood

Unlike traditional frameworks that use complex VDOM subtree replacement or virtual state hydration during HMR, DriftJS is able to perform simple component re-instantiation due to its VM boundary architecture.

When a `.drift` component is loaded, `driftjs-vite-plugin` compiles the file and returns a JavaScript file structured as follows:

```javascript
// Generated by driftjs-vite-plugin at build/dev time
import { CompiledModule } from 'driftjs-dom'

const App = {
  // Constant pool containing tag names, text, and AST trees
  constants: [
    "App container", // Static Text
    { type: "Program", body: [...] }, // Compiled JS Script block AST
    "count", // State variable reference
    // ...
  ],
  // Bytecode instruction stream
  bytecode: new Uint8Array([
    12, 1,          // EXEC_SCRIPT constants[1]
    1, 0, 0,        // CREATE_ELEMENT r0 tag_name_idx
    7, 1, 2,        // INTERPOLATE_TEXT r1 expr_idx
    4, 0, 1,        // APPEND_CHILD r0 r1
    0, 0            // RETURN r0
  ]),
  // Dependency relationships for reactive updates
  reactiveBindings: [
    { pc: 5, deps: ["count"] }
  ]
}

export default App

// ── Vite HMR Glue Code ──
if (import.meta.hot) {
  import.meta.hot.accept((newModule) => {
    if (newModule) {
      // Re-trigger mounting VM execution when bytecode changes
      window.__DRIFT_DEV_RELOAD__?.(newModule.default)
    }
  })
}
```

### Hot Reload Execution Flow
1. When Vite notifies the browser that `App.drift` has changed, the new module is accepted.
2. The HMR controller registers the new `CompiledModule` containing the updated bytecode.
3. The running `DriftClientVirtualMachine` clears the target container DOM, resets the internal virtual registers (r0–r255) and variables scope, and re-executes the updated bytecode from PC = 0.
4. Because compilation is fast (typically under 1ms) and the runtime VM bytecode executes linearly in microseconds, the full reload occurs with no noticeable lag.

## 🛠️ VS Code Integration

To ensure the best development experience, install the official VS Code extension:
- **Syntax Highlighting**: Supports HTML directives (`@if`, `@for`, `@switch`), interpolated expressions, and standard CSS/JS tags.
- **Diagnostic Checks**: Checks for basic compiler syntax errors (like mismatched directive tags or invalid expressions) directly inside your editor.

### Installing VS Code Support
The extension package is located in `packages/vscode-plugin`. To compile and install it manually:

```bash
cd packages/vscode-plugin
pnpm install
pnpm run compile
# Install the generated .vsix package inside VS Code
code --install-extension drift-vscode-0.0.1.vsix
```
